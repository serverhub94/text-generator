# Генератор SEO-текстов для iGaming

Веб-форма, которая превращает вводные редактора (ключевой запрос, GEO, язык,
семантика из Ahrefs) в готовый деливеринг: ресёрч-отчёт → ТЗ → статья в HTML.
Поднимается отдельным Laravel-приложением на сабдомене рядом с существующим
проектом команды.

Человек заполняет форму, выбирает режим V1–V7 — приложение ставит задачу в
очередь, гоняет конвейер стадий через Claude и отдаёт результат по ссылке.
Полный цикл идёт минутами, поэтому страница прогона опрашивает статус, а не
держит открытым HTTP-соединение.

---

## Главное правило: никаких выдуманных цифр

Это причина существования проекта, а не пожелание. Прежний подход просил
модель «проанализировать URL» — она выдумывала цифры.

Единственный допустимый источник чисел (volume, KD, DR, трафик, беклинки) —
блок `SUPPLIED DATA`, который человек вставляет из Ahrefs. Чего там нет —
пишется `нет данных`. Не «примерно», не среднее по списку, не перенос с
похожего ключа.

Из веба модель берёт только наблюдения: структуру страниц конкурентов,
заголовки, показываемые бренды, формулировки PAA-вопросов. Наблюдение никогда
не подаётся как метрика Ahrefs.

Правило живёт в [`resources/prompts/rules.md`](resources/prompts/rules.md)
и закреплено тестом `PromptRepositoryTest::test_the_no_invented_data_rule_survives_editing`.
Правите промпты — не вычищайте его.

## Как это устроено

### Конвейер

Стадии идут **одной растущей перепиской**, а не независимыми запросами: когда
модель пишет ТЗ, она видит свой ресёрч; когда пишет текст — видит и ресёрч, и
ТЗ. Это одновременно качество и деньги: стабильный префикс переписки читается
из кеша API, поздние стадии дешевле ранних.

| Стадия | Что делает | Ходит в веб |
| --- | --- | --- |
| `entities` | разбор сущностей запроса | да |
| `research` | выдача по GEO, конкуренты, content gap | да |
| `paa` | реальные People-Also-Ask вопросы Google | да |
| `masterplan` | мастер-план страницы (только V7) | нет |
| `brief` | ТЗ на текст | нет |
| `article` | сама статья | нет |
| `audit` | проверка текста, вердикт | нет |

Если аудит выносит «НЕ ПРОШЁЛ», режимы V4/V5 переписывают статью и проверяют
заново — не больше отведённого числа попыток.

### Режимы

| Режим | Стадии | Effort | Потолок выхода |
| --- | --- | --- | --- |
| V1 · Базовый | article | low | 16k |
| V2 · Улучшенный | brief → article | medium | 24k |
| V3 · Максимальный | research → brief → article | high | 32k |
| V4 · Pro + Проверка | research → brief → article → audit (+2 переписывания) | high | 32k |
| V5 · PAA + E-E-A-T | research → paa → brief → article → audit (+2 переписывания) | xhigh | 48k |
| V6 · Editorial | research → brief → article → audit | xhigh | 48k |
| V7 · Моно-статья | entities → research → masterplan → article → audit | xhigh | 64k |

Полное описание — в [`config/textgen.php`](config/textgen.php).

### Ключевые классы

| Файл | Ответственность |
| --- | --- |
| `app/Services/Pipeline.php` | порядок стадий, растущая переписка, цикл переписывания после аудита |
| `app/Services/ClaudeService.php` | обёртка над Anthropic SDK; всегда стримит (иначе HTTP-таймаут), считает токены и стоимость |
| `app/Services/Contracts/TextModel.php` | контракт ради тестов: конвейер прогоняется без расходов |
| `app/Services/PromptRepository.php` | загрузка промптов из `.md`, подстановка `{{ name }}` |
| `app/Support/KeywordParser.php` | разбор вставленной семантики в «ключ + частотность» |
| `app/Support/ArticleDocument.php` | разбор ответа стадии ARTICLE на мету, разметку и заметки |
| `app/Support/HtmlFragment.php` | пересборка HTML по белому списку тегов и атрибутов |
| `app/Support/BudgetGuard.php` | месячный потолок расходов |
| `app/Jobs/RunPipeline.php` | прогон в очереди (`tries = 1`, `timeout = 3600`) |

Модель — `claude-opus-5` везде. Веб-поиск и чтение страниц — серверные
инструменты Anthropic, своей инфраструктуры парсинга нет.

### Формат выдачи статьи

Деливеринг — **HTML-фрагмент, который вставляется между `<body>` и `</body>`**:
без `class`, `style`, `id`, без `<div>`/`<span>`, без обёртки документа.
Разрешены только структурные теги, из атрибутов — `href` у `<a>` и
`colspan`/`rowspan` у ячеек. Разметка не проверяется, а пересобирается
`HtmlFragment`: разбирается в DOM, остаётся белый список, печатается заново.

Стадия ARTICLE отдаёт три секции с маркерами `===META===`, `===HTML===`,
`===NOTES===`: on-page мета, разметка и служебные пометки редактору.
Остальные стадии — рабочие markdown-документы для человека, не для CMS.

### Языковые конвенции

| Что | Язык |
| --- | --- |
| Ключи, заголовки, вопросы, бренды | язык рынка |
| Объяснения, выводы, предупреждения | русский |
| Инструкции внутри ТЗ | английский |
| On-page: title, meta, H1–H3, анкоры, текст | язык рынка |
| Поле, которое заполняет человек | `**добавьте данные**`, в статье — `<strong>добавьте данные</strong>` |

GEO — две буквы (`PL`, `CA`, `UK`); язык — `lang-LANG` (`en-GB`, `es-AR`).
`UK` → ISO `GB` мапится в `ClaudeService::toIsoCountry()`: команда пишет `UK`,
а геотаргетинг поиска требует `GB`.

## Требования

- PHP **8.3+** с расширениями `dom`, `libxml`, `mbstring`, `json`, `curl`,
  `pdo_sqlite` (для локальной разработки) или `pdo_mysql` (для сервера)
- Composer
- Ключ Anthropic API
- Node.js **не нужен** — ассетов нет, стили встроены в `resources/views/layout.blade.php`

## Запуск локально

```bash
# зависимости
composer install

# конфигурация
cp .env.example .env
php artisan key:generate

# локальная база — SQLite
touch database/database.sqlite
php artisan migrate
```

Затем впишите в `.env` ключ:

```ini
ANTHROPIC_API_KEY=sk-ant-...
```

Дальше нужны **два процесса** — веб и воркер очереди:

```bash
php artisan serve        # терминал 1 → http://localhost:8000
php artisan queue:work   # терминал 2
```

> **Без воркера прогон навсегда зависнет в статусе «В очереди».** Форма только
> ставит задачу; всю работу делает очередь.

Не используйте `composer setup` из `composer.json` — этот скрипт до сих пор
зовёт `npm install` и `npm run build` и сломается на машине без Node
(см. `CLEANUP.md`, пункт У5).

### Первый прогон

Живого прогона против настоящего Anthropic API не было ни разу. **Первый
прогон делайте режимом V1** — он самый дешёвый и не ходит в веб.

## Конфигурация

Всё специфичное для генератора живёт в
[`config/textgen.php`](config/textgen.php) и читается через
`config()`, а не через `env()` в рантайме — иначе приложение падало бы после
рекомендованного `php artisan config:cache`.

| Переменная | По умолчанию | Что делает |
| --- | --- | --- |
| `ANTHROPIC_API_KEY` | — | ключ API; без него приложение падает сразу и внятно |
| `TEXTGEN_MODEL` | `claude-opus-5` | модель |
| `TEXTGEN_ACCESS_CODE` | пусто | пусто = форма открыта; строка = один код на команду |
| `TEXTGEN_RUNS_PER_HOUR` | `5` | лимит запусков с одного IP в час |
| `TEXTGEN_RUNS_PER_DAY` | `20` | лимит запусков с одного IP в сутки |
| `TEXTGEN_MONTHLY_BUDGET_USD` | `200` | потолок расходов за календарный месяц; `0` = без потолка |
| `TEXTGEN_PRUNE_AFTER_DAYS` | `7` | через сколько дней удалять прогоны |
| `TEXTGEN_MAX_SEARCHES` | `12` | потолок поисковых запросов на стадию |
| `TEXTGEN_MAX_FETCHES` | `10` | потолок чтений страниц на стадию |

Форма открыта без авторизации — так решил владелец. Поэтому лимиты по IP и
месячный потолок расходов не декоративные: это единственное, что защищает
API-ключ. `TEXTGEN_ACCESS_CODE` закрывает форму, если понадобится.

Обслуживание:

```bash
php artisan textgen:prune   # удалить прогоны старше TEXTGEN_PRUNE_AFTER_DAYS
```

Команда уже стоит в планировщике (`routes/console.php`, ежедневно в 04:00) —
на сервере нужен только `schedule:run` в cron.

## Выкладка на сервер

Полная инструкция — [`DEPLOY.md`](DEPLOY.md): nginx, systemd-юнит
воркера, права, cron, проверка.

Три вещи, о которых чаще всего забывают:

1. **Очередь обязательна.** Нет воркера — нет прогонов.
2. **`--timeout` воркера должен превышать `$timeout` в `RunPipeline`** (3600),
   иначе задача обрывается на середине.
3. **После каждой выкладки** — `php artisan queue:restart`: воркер держит код
   в памяти.

---

## Что стоит знать перед правками

- **Повторов нет** (`tries = 1`): каждая попытка стоит денег, а падение почти
  всегда означает проблему во вводных, а не сетевой сбой.
- **Ассетов нет.** Стили встроены в `resources/views/layout.blade.php`, npm на
  сервере не нужен. Не добавляйте сборку без причины.
- **Истории в интерфейсе нет.** Прогоны хранятся только ради опроса статуса и
  чистятся `textgen:prune`.
- **Промпты правит редактор, а не программист.** Они лежат отдельными
  `.md`-файлами в `resources/prompts/`; незаполненный плейсхолдер `{{ name }}`
  роняет прогон, а не уезжает в промпт молча.

Известные проблемы и ТЗ по ним: [`FIXES.md`](FIXES.md)
(конвейер и деньги) и [`CLEANUP.md`](CLEANUP.md) (уборка).
Оба составлены по ревью и **не выполнены** — перед правками загляните туда,
скорее всего задача уже описана.

## История генераций

В приложении появилась страница **История генераций**, где хранятся записи предыдущих прогонов. Раздел позволяет быстро найти нужный прогон, повторить его или удалить.

### Доступ и видимость
- Видимость записей контролируется настройкой **`textgen.history_scope`**:
  - **`session`** — показываются только прогоны текущей сессии.
  - **`all`** — показываются все прогоны (для администраторов или при необходимости).
- По умолчанию используется значение из конфига `config/textgen.php`.

### Фильтры и поиск
На странице доступны фильтры и поиск для быстрого отбора записей.

| Параметр | Тип | Описание |
|---|---:|---|
| `status` | string | Фильтр по статусу прогона (`queued`, `running`, `done`, `failed`). |
| `mode` | string | Фильтр по режиму генерации (ключ из `textgen.modes`). |
| `model` | string | Фильтр по модели (ключ из `textgen.models`). |
| `q` | string | Поиск по `target_query` и по `input->target_query` (частичное совпадение). |
| `page` | integer | Номер страницы для пагинации (25 записей на страницу). |


### Кнопка Повторить
- **Назначение**: создать новый прогон с теми же входными данными, что и у выбранного прогона.
- **Поведение**:
  - При нажатии формируется новый `Run` с `input` скопированным из исходного прогона.
  - Новая запись получает новый `uuid`, текущую `session_id` и выбранную модель сохраняют в поле `model`.
  - После создания запускается pipeline (через `RunPipeline::dispatch($run->id)`).
- **Реализация**: кнопка ведёт на маршрут создания прогона с параметром `from={uuid}` или вызывает контроллер, который клонирует `input` и создаёт новый `Run`.

### Удаление прогона
- **Правила удаления**:
  - Если `textgen.history_scope = 'session'`, удалять можно только прогоны, принадлежащие текущей сессии.
  - Если `history_scope = 'all'`, удаление доступно в соответствии с правами приложения.
- **Маршрут**: `DELETE /runs/{run}`.
- **Поведение**:
  - При успешном удалении пользователь перенаправляется на страницу истории с уведомлением.
  - Прогоны удаляются из базы данных; если требуется мягкое удаление, реализуйте `softDeletes` в модели `Run`.
- **Безопасность**: проверяйте принадлежность сессии через метод `isOwnedBySession(session()->getId())` перед удалением.

### Примечания по конфигурации и обслуживанию
- Параметр очистки старых прогонов: `textgen.limits.prune_after_days` (по умолчанию можно установить 90 дней). Команда очистки: `php artisan textgen:prune`.
- Если в таблице `runs` есть записи без `uuid`, рекомендуется выполнить backfill и добавить уникальный индекс на `uuid`.
