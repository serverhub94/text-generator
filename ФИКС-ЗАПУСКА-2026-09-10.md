**Дата:** 2026-09-10
**Ветка:** `text-generator-ivan`
**Точка отсчёта:** HEAD = `2e1339b`

## Короткий ответ

Один файл: **`app/Services/ClaudeService.php`**, метод `send()`, блок сборки
параметров запроса к SDK.

Всё остальное для запуска V1 уже было на месте (ключ в `.env`, миграции,
`config/textgen.php` с `thinking => 'none'` строкой после коммита `2e1339b`).

---

## Симптом

Любой реальный прогон (V1 в том числе) падал сразу на стадии `article`:

```
Anthropic\Core\Exceptions\BadRequestException  (HTTP 400)
invalid_request_error
output_config.max_output_tokens: Extra inputs are not permitted
```

Стек: `ClaudeService::send()` → `MessagesService->createStream()`.

## Причина

Фича выбора модели (`74ed83c`) переписала сборку параметров в `send()` так, что
при заданном `ModelProfile` она клала в запрос

```php
outputConfig: ['max_output_tokens' => 16000]
```

API Anthropic поле `output_config.max_output_tokens` (и camelCase-вариант
`maxOutputTokens`, который правил коммит `2e1339b`) **не принимает**. Потолок
выхода задаётся только верхнеуровневым `max_tokens` (аргумент `maxTokens`
у `createStream`). Рабочая до-фичевая форма запроса была:

```php
thinking:     ['type' => 'adaptive'],
outputConfig: ['effort' => $effort],
```

Плюс фича выкинула из `output_config` ключ `effort`, который там валиден и нужен.

## Исправление

Вернул набор передаваемых полей к до-фичевой форме. `ModelProfile`, если он
задан, теперь только **ужимает** значения под возможности модели, не меняя
структуру запроса:

| параметр | без профиля | с профилем |
|---|---|---|
| `thinking` | `['type' => 'adaptive']` | то же |
| `outputConfig` | `['effort' => $effort]` | `['effort' => $profile->effortFor($effort)]` — понижение до ближайшего поддерживаемого уровня |
| `maxTokens` (верхнеуровневый) | `$maxTokens` из режима | `$profile->maxTokensFor($maxTokens)` — обрезка по `max_output_tokens` модели |
| `tools` | веб-инструменты по флагу стадии | то же, но отключаются, если `$profile->webTools() === 'none'` |

Ключ `max_output_tokens` в `output_config` не отправляется никогда.
Также убран двойной вызов `createStream` (ветка «с `outputConfig` / без») —
`outputConfig` теперь всегда непустой, ветвление не нужно.

## Как проверить

Разовый прогон без `serve` / `queue:work` — через tinker-скрипт:

```php
// v1run.php
use App\Models\Run;
use App\Jobs\RunPipeline;
use App\Services\Pipeline;

$run = Run::create([
    'status'       => Run::STATUS_QUEUED,
    'mode'         => 'v1',
    'input'        => ['mode'=>'v1','target_query'=>'best online casinos in Canada','geo'=>'CA','language'=>'en-CA'],
    'ip'           => '127.0.0.1',
    'model'        => 'opus-5',
    'target_query' => 'best online casinos in Canada',
    'session_id'   => 'cli-test',
]);

(new RunPipeline($run->id))->handle(app(Pipeline::class));

$run->refresh();
echo $run->status, ' ', $run->cost_usd, PHP_EOL;
```


## Что НЕ трогали (но всё ещё сломано на ветке)

Отдельно от живого прогона на ветке лежат **21 падающих теста** (67/88).
Эта правка их не меняет — там свои причины:

- `config('textgen.default_model')` = `claude-opus-5`, а ключи реестра моделей —
  `opus-5` / `sonnet-5` / `haiku-4-5` → «Unknown model» (16 ошибок `PipelineTest`).
  Живой прогон это не задевает: форма и `RunPipeline` подставляют валидный ключ
  (`opus-5`) в `$input['model']`, до `default_model` дело не доходит.
- `stage` (ед. ч.) отсутствует в `Run::$fillable` (2 `GeneratorTest`).
- `env()` в `ClaudeService.php` (строка с `TEXTGEN_MAX_CONTINUATIONS`) — 1 `ConfigCacheTest`.
- `SHOW COLUMNS` под sqlite в `RunPipelineTest` (1).
- `AccessCodeTest` постит на `/`, а не на `/access` (2).
- `tests/Support/FakeTextModel::send()` не хватало параметра `?ModelProfile $profile`
  (правка уже в рабочем дереве, незакоммичена — без неё падал весь suite).
